# XD 用量布局恢复

根据用户提供的原版截图，Hub 模式的用量页恢复 XD 原有信息排列和主题：顶部维度按钮及时间范围，四张统计卡片，左侧热门排行、右侧流量趋势，下方用量详情表。顶部和实例页统一使用“用量”入口；表格支持搜索、排序以及与排行同步高亮。手机按单列排列，上传/下载在行内紧凑展示。

数据继续来自 Hub 的服务端历史 API，与浏览器 IndexedDB 独立。所有查询共享实例范围和完整 UTC 时间桶；更换筛选会清空旧数值并取消旧请求。上传/下载/总量卡片读取实例总量，排行和详情读取当前维度 TOP 20 的采样归因；条目计数明确标为 TOP 20，搜索排序不改变卡片和趋势，也不补造连接次数。

覆盖率、归因差额、采集缺口与分页连接摘要收进默认关闭的采集详情；总量不一致及观测覆盖不完整仍在主视图提示。无观测桶保留空白，孤立的有效桶显示圆点，避免稀疏历史被画成空图。

沿用 [ADR-007](adr/007-hub-frontend-boundary.md) 的数据边界：现有设备/主机/代理/规则/进程五种独立维度，未增加联合聚合表，不提供设备→域名→代理的跨维度流量钻取；连接生命周期量仍仅作摘要。保留策略继续由 Hub 管理，没有重新接入浏览器“永久保存/清空全部”操作。

验证覆盖服务端数据适配、未知标签/零值、排序/搜索且不更改原始数据，以及实际 Chromium 中的五维度切换、四张统计卡片、总量不受搜索影响、表格排序/筛选/高亮、稀疏历史点、采集详情折叠、窄屏、错误清空/重试、会话失效、增删改与保留历史。

截图使用本地临时 Fake Controller 数据，输出到忽略目录 test-results/hub-usage-desktop.png、hub-usage-mobile.png 和 hub-usage-table-mobile.png。构建与验证均在本地进行。

验证结果：前端 typecheck 和 ESLint 通过，64 个测试文件共 714 项单元测试通过；Go 全量 race 与 vet 通过。内嵌产物使用本地 Chromium 验收，稀疏历史点的中心坐标位于真实绘图区内且已结束动画，避免仅检查 SVG 节点存在却遗漏不可见数据点。Docker 验收包含嵌入资源、密码登录、默认管理采集、重启持久化及备份恢复。
