# ADR-010：自动初始化与网页首次密码设置

状态：采用。用户要求隐藏命令行初始化，首次启动自行初始化，在第一次打开网页时设置 Hub 密码。本决策替代部署前必须运行 `init` 的流程，不改变单管理员、同源 Session 或双仓库边界。

## 状态与启动

数据库管理员记录是首次设置是否完成的唯一依据，不另存配置开关。空数据库直接启动，自动执行迁移并生成 32 字节主密钥，文件权限 0600；没有默认密码。待设置时服务探活成功，管理 API、Gateway 和 WebSocket 仍要求有效 Session。根页面跳转到现有 `/login` 入口，同源脚本读取设置状态并展示设置/确认密码表单。

已有数据库和主密钥继续使用，不重新设置密码或改写内部历史用户名。只有没有管理员和实例数据的数据库才允许自动创建缺失密钥；已有数据缺少密钥、密钥损坏或权限不正确时拒绝启动，避免生成替代密钥破坏旧凭据。旧 `init` 命令仅保留向后兼容，部署文档不再需要此步骤。

## 首次设置

公开的 `GET /api/v1/auth/setup` 仅返回是否需要设置及密码长度边界。`POST` 接受密码和确认值，使用与登录相同的 Host/Origin/Referer 校验、IP 限流、请求体上限与两个并行 Argon2id 计算名额。设置 API 不提供密码重置能力。

管理员插入采用数据库主键和 `ON CONFLICT DO NOTHING`，与成功审计在同一事务提交；并发请求仅一个成功，后续请求返回 409。成功后自动创建普通 Session，复用现有 Cookie、CSRF 和会话旋转流程。旧引导页面发现设置已完成时切回登录，不覆盖密码。首次入口使用原部署的 loopback、Tailnet ACL 或受限反代，由部署者完成第一次设置。

## 边界和验证

登录/引导由 Go 的公开 Web shell 提供，无需更改 XD Fork、增加 Node 服务或更换静态 UI 锁定版本。数据库 Schema 保持 5；已有数据库、实例凭据、导入 YAML 及历史均兼容。

验证覆盖自动建库/密钥权限、管理接口拒绝匿名、密码长度与确认、同源校验、并发单次创建与审计回滚、自动会话、旧引导页冲突、重启保留、缺密钥拒绝、真实 CLI/浏览器/非 root 只读容器及备份恢复。
